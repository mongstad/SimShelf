# Issue #109 — Compact parameter rows and required feedback

Validated on 2026-10-20 on Linux, Python 3.14.8 and Chromium. Accepted main:
`ed2a113` (0.1.0.38); proposed application version: **0.1.0.39**.

## Scope and decisions

`ArgumentEditor.tsx` and `style.css` align each name/enable block with its value,
move type metadata beside the name, use an accessible required-only asterisk,
bound numeric/select widths to 16rem and string widths to 24rem, and give help
12px top spacing plus bottom padding. Below 600px, values stack beneath their
names. Checkbox and name metadata wrap as a unit; editable strings remain whole.
Flags have no value field or value heading.

`parameterRows.ts` projects unambiguous required omissions through the existing
validator. `LaunchSimulation.tsx` lets validation/save/start attempts reveal these
rows, clear a hiding search and focus the first omitted input/flag. The existing
validation guards still return before requests or launch. Correcting omissions
clears their borders and concise, associated error text. Successful validation
does not reset search. No defaults are inserted, values coerced or flags invented.
Other validation errors retain their existing diagnostics. Explicit empty strings
remain supplied string values; invalid numeric strings retain typed diagnostics.

`parameterPresentation.ts` also searches the displayed integer/string type names.
The existing required-first groups, manual rows, exact argv and explicit saved
manual-mode bypass are retained. #104 is merged; #107 wording and #108 collapsible
collections remain separate work, not prerequisites or implemented subissues.
There are no backend, SWSS, storage/schema, solver or historical-record changes.

## Failures and limitations

Sandboxed Node reported file-level results rather than individual cases, and the
sandboxed Python TestClient stalled; it was interrupted and focused checks passed
outside the sandbox. Initial packaging lacked setuptools; declared build tools
were installed only in a disposable environment. The first local-server command
used unsupported `--no-browser`; corrected to `--no-open`. A search-type test
initially matched `int` in shared help text ("Integration"); isolated fixture help
corrected the assertion. Browser checks caught and corrected an unwanted search
reset on successful validation and isolated-checkbox wrapping for long names.
Pip reported an unavailable cache in the sandbox.

No real scientific solver, GPU workload, Windows/macOS, other browser engine,
actual screen reader or exhaustive backend suite was tested. Native one-line
text controls scroll long values horizontally; they do not truncate stored text.
Build checks reuse installed runtime dependencies through a disposable `.pth`;
this is not clean dependency-resolution certification. No release/publication.
